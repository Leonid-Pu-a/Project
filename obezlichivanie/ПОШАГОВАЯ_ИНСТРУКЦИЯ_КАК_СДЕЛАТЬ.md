# Пошаговая инструкция для новичка: как сделать задание по обезличиванию CIM-модели

Это руководство для того, кто впервые видит CIM-модель и только начинает программировать на Python.
Вы пройдёте весь путь сами, маленькими шагами: от «что такое XML» до готовой программы, которая
обезличивает настоящую модель энергосистемы размером почти 1 ГБ.

Всё нужное лежит в папке `C:\MX\новый вариант`. В ней два руководства:

* **эта инструкция** — как **сделать** решение самому, шаг за шагом;
* `ИНСТРУКЦИЯ_НОВИЧКУ.md` — как **пользоваться** готовой программой: запуск, проверка, частые ошибки.

Все выводы программ в этой инструкции настоящие: каждый шаг выполнен в этой папке.

**Как устроен каждый шаг:**

* **Зачем** — какую часть задачи решает шаг;
* **Что понять** — новые понятия простыми словами;
* **Что сделать** — команды и код (готовый код лежит в папке `practice/`, его можно запускать сразу);
* **Что вы увидите** — настоящий вывод программы, чтобы сверить свой результат;
* **Проверьте себя** — вопросы, на которые нужно уметь ответить, прежде чем идти дальше;
* **Частые ошибки** — на чём обычно спотыкаются.

Сначала все шаги делаются на **учебной мини-модели** `practice/mini_model.xml` (15 объектов, одна
страница), и только в конце — на настоящем файле `input.xml`. Так любую ошибку видно сразу, а не
через 4 минуты обработки.

**Сколько времени нужно:** около 2–3 вечеров. Части 1–3 — первый вечер, шаги 1–9 — второй,
шаги 10–14 и оформление — третий.

## Часть 1. Понять задачу простыми словами

### Что такое обезличивание

Представьте, что вам дали книгу, в которой упоминаются настоящие люди и города, и попросили
подготовить её для публикации так, чтобы никого нельзя было узнать. Нужно:

1. **Заменить** имена и названия на выдуманные, а не просто вычеркнуть их: книгу должно быть можно
   читать, сюжет должен сохраниться.
2. Заменять **последовательно**: если «Иванов» в первой главе стал «Петровым», то и в десятой главе
   он должен быть «Петровым». Иначе непонятно, кто есть кто.
3. **Не менять сюжет**: кто с кем встречался, кто кому писал письма, сколько было глав.

С моделью энергосистемы всё то же самое. Модель — это «книга» об энергосистеме: подстанции, линии,
счётчики, абоненты и связи между ними. Её хотят передать студентам, подрядчикам или разработчикам,
но в ней есть **персональные данные** (ФИО и адреса абонентов) и **чувствительные данные**
(настоящие названия подстанций и линий, номера счётчиков).

Такая замена с сохранением связей называется **псевдонимизацией**: каждое настоящее значение
получает постоянный «псевдоним».

### Требования задания простыми словами

| Требование | Что это значит на практике |
|---|---|
| ФИО абонентов и сотрудников → синтетические из справочника имён | «Nikitin Vitaliy Artemov» → «Zakharov Timofey Timofeevich»; имена берутся из нашего списка |
| Из имени получаются фамилия, отчество, e-mail, улица | из одной строки справочника «Пётр» получаем «Петров», «Петрович», «Петровская» |
| Названия объектов и организаций → прилагательные от фруктов | «Sub 35 kV Ngolona» → «Sub 35 kV Alychovaya» |
| Номера → случайные цифры той же длины | «52073867» → «23320503» |
| Свободный текст (комментарии, вложения) — найти и замаскировать | формулы, шаблоны записей, XML внутри base64 |
| Одинаковый вход → одинаковый результат | запустили дважды — получили один и тот же файл |
| Ссылки не ломаются | если линия ссылалась на подстанцию, то и после замены ссылается на неё же |
| Тип объекта, напряжение, район сохраняются | «Sub» остаётся «Sub», «35 kV» остаётся «35 kV» |
| Новые названия уникальны | две разные подстанции не получат одинаковое название |
| Статистика модели не меняется | объектов, связей и нагрузок столько же, сколько было |

### Что получится в конце

Две программы:

* `anonymize.py` — читает модель и пишет обезличенную копию;
* `check.py` — сравнивает исходник и копию и сообщает, все ли требования выполнены.

## Часть 3. Знакомство с XML и CIM на мини-модели

Откройте `practice/mini_model.xml` в редакторе. Разберём, из чего он состоит.

### 3.1 XML — это дерево тегов

```xml
<?xml version="1.0" encoding="utf-8"?>                          ← заголовок: это XML в UTF-8
<rdf:RDF xmlns:rdf="http://www.w3.org/..." xmlns:cim="http://iec.ch/...">   ← корень всего файла
  <cim:Substation rdf:about="#_b2000000-0000-4000-8000-000000000001">     ← начало объекта
    <cim:IdentifiedObject.name>Sub 35 kV Ngolona</cim:IdentifiedObject.name> ← поле со значением
    <cim:Substation.Region rdf:resource="#_a1000000-0000-4000-8000-000000000001" /> ← ссылка
  </cim:Substation>                                              ← конец объекта
</rdf:RDF>
```

* **Тег** — то, что в угловых скобках: `<cim:Substation>`. Открывающий и закрывающий теги
  (`</cim:Substation>`) образуют **элемент**, внутри него могут быть другие элементы.
* **Атрибут** — `rdf:about="…"` внутри открывающего тега.
* **Префикс** (`cim:`, `rdf:`, `me:`) — сокращение для длинного адреса, объявленного в корне
  (`xmlns:cim="http://iec.ch/TC57/2014/CIM-schema-cim16#"`). Python будет показывать не `cim:`,
  а полный адрес в фигурных скобках: `{http://iec.ch/TC57/2014/CIM-schema-cim16#}Substation`.

### 3.2 CIM — это объекты классов и ссылки между ними

CIM (Common Information Model, стандарты МЭК 61970-301 и 61968-11) описывает энергосистему так:

* **Класс** — вид объекта: `Substation` (подстанция), `Line` (линия), `ACLineSegment` (участок линии),
  `Customer` (абонент), `Meter` (счётчик), `Person` (сотрудник).
* **Объект** — конкретная подстанция. У каждого объекта есть **уникальный идентификатор** UUID
  в атрибуте `rdf:about`: `#_b2000000-0000-4000-8000-000000000001`.
* **Поле** — свойство объекта: `IdentifiedObject.name` (название), `ACLineSegment.r` (сопротивление).
  Перед точкой стоит класс, в котором поле определено: название есть у всех объектов, поэтому оно
  определено в общем «родительском» классе `IdentifiedObject`.
* **Ссылка** — поле с атрибутом `rdf:resource="#_…"`. Это связь «этот объект относится к тому».

### 3.3 Нарисуйте мини-модель

Возьмите лист бумаги и нарисуйте объекты мини-модели кружками, а ссылки — стрелками:

```
ACLineSegment ──Equipment.EquipmentContainer──► Line
ACLineSegment ──ConductingEquipment.BaseVoltage──► BaseVoltage (35 kV)
Substation (Ngolona) ──Substation.Region──► SubGeographicalRegion (Koulikoro District)
Substation (2303)    ──Substation.Region──► SubGeographicalRegion
Meter ──EndDevice.UsagePoint──► UsagePoint
```

Это **граф связей**. Задание требует, чтобы после обезличивания граф остался таким же, изменились
только «подписи» на кружках.

### 3.4 Особые случаи, которые есть в модели

| Что | Пример из мини-модели | Почему важно |
|---|---|---|
| Ссылка на перечисление, а не на объект | `rdf:resource="http://iec.ch/...#CustomerKind.residential"` | это не UUID, менять не нужно |
| Вложенная структура | адрес в `ServiceLocation`: `StreetAddress → StreetDetail → name` | значения бывают глубоко внутри |
| base64 | `ACLineSegment.sections` = `77u/PD94bWwg…` | внутри закодирован XML с настоящими названиями |
| Имена в формулах | `abs(ПС_Ngolona_P_Ф_01)` | имя подстанции спрятано внутри формулы |
| Число как название | у счётчика `IdentifiedObject.name` = `52073867` | это заводской номер — его тоже нужно скрыть |
| Число как физика | `ACLineSegment.r` = `0.123` | сопротивление трогать нельзя |

**Проверьте себя:** что такое `rdf:about` и `rdf:resource` и чем они отличаются? Почему нельзя
поменять UUID у объекта и не поменять его в ссылках? (Ответ: ссылка будет вести «в никуда».)

## Шаг 1. Прочитать XML на Python

**Зачем.** Убедиться, что Python «видит» объекты, поля и ссылки так же, как вы на бумаге.

**Что понять.** Модуль `xml.etree.ElementTree` (сокращённо `ET`) входит в Python. `ET.parse(путь)`
читает файл целиком и строит дерево. `for obj in root` перебирает детей корня, то есть объекты
модели. `obj.get(атрибут)` возвращает значение атрибута, `field.text` — текст внутри элемента.

**Что сделать.** Откройте `practice/step01_read_xml.py`, прочитайте комментарии и запустите:

```bash
python practice/step01_read_xml.py
```

**Что вы увидите** (фрагмент):

```
Корень: RDF | объектов внутри: 15

Объект класса Substation, идентификатор #_b2000000-0000-4000-8000-000000000001
   IdentifiedObject.mRID = 'b2000000-0000-4000-8000-000000000001'
   IdentifiedObject.name = 'Sub 35 kV Ngolona'
   IdentifiedObject.mRIDStr = 'sub_substation_23905460'
   Substation.Region -> ссылка на #_a1000000-0000-4000-8000-000000000001
...
Объект класса ServiceLocation, идентификатор #_a7000000-0000-4000-8000-000000000001
   Location.mainAddress -> вложенная структура
```

**Проверьте себя.**
1. Сколько ссылок у объекта `ACLineSegment`? (Две внутренние: на линию и на напряжение.)
2. Что вернёт `obj.get(RDF + "about")`, если атрибута нет? (`None`.)
3. Зачем функция `local(tag)`? (Отрезать `{http://…}` от имени тега.)

**Упражнение.** Допишите в скрипт подсчёт: сколько всего ссылок в файле.

**Частые ошибки.** Писать `obj.get("rdf:about")`: так атрибут не найдётся, нужно полное имя
`"{http://www.w3.org/1999/02/22-rdf-syntax-ns#}about"` (в коде это `RDF + "about"`).

## Шаг 2. Читать файл потоком

**Зачем.** `ET.parse` загружает весь файл в память. Для файла в 1 ГБ это около 10 ГБ оперативной
памяти: компьютер начнёт тормозить или программа упадёт. А в задании говорится о файлах в десятки
гигабайт.

**Что понять.**

* `ET.iterparse` читает файл **по кусочкам** и сообщает о **событиях**: «начался тег» (`start`) и
  «закончился тег» (`end`).
* Мы считаем **глубину**: корень — 1, объекты — 2, поля — 3 и глубже. Когда закончился элемент
  глубины 2, объект прочитан целиком: отдаём его на обработку и **удаляем** из памяти
  (`root.remove(elem)`). В памяти всегда находится только один объект.
* `yield` превращает функцию в **генератор**: она отдаёт значения по одному, когда их просят
  (`for obj in read_objects(...)`), и «замирает» между ними.

**Что сделать.**

```bash
python practice/step02_stream.py practice/mini_model.xml
```

Затем попробуйте на настоящем файле (около 40 секунд):

```bash
python practice/step02_stream.py C:\Users\Admin\Downloads\input.xml
```

**Что вы увидите.**

```
Объектов: 15, классов: 12, время: 0.0 с
       3  Customer
       2  Substation
       1  SubGeographicalRegion
...
```

На `input.xml` будет 741 550 объектов и 263 класса. Откройте «Диспетчер задач» во время работы:
памяти программа занимает немного, и это значение не растёт.

**Проверьте себя.** Почему мы проверяем `depth == 1` **после** уменьшения глубины? (Элемент глубины 2
закончился, после `depth -= 1` глубина стала 1.)

**Частые ошибки.** Забыть `root.remove(elem)`: тогда память растёт так же, как при `ET.parse`.

## Шаг 4. Заменить идентификаторы (UUID) и не сломать связи

**Зачем.** UUID объекта — тоже «идентификатор энергообъекта», его нужно заменить. Но все ссылки на
объект должны указывать на него и дальше.

**Что понять.**

* **Хеш-функция** (у нас SHA-256) превращает любой текст в длинное число. Одинаковый текст всегда
  даёт одинаковое число, а по числу исходный текст не восстановить.
* Если добавить к тексту **секретное слово**, посторонний не сможет повторить вычисление:
  `h(текст) = SHA-256(секрет + "|" + текст)`.
* Новый UUID = UUID, построенный из хеша старого. Если **одной и той же функцией** заменить UUID и в
  `rdf:about`, и в `rdf:resource`, ссылка автоматически укажет на тот же объект. Никакая таблица
  соответствия для этого не нужна.

**Что сделать.**

```bash
python practice/step04_uuid.py
```

**Что вы увидите.**

```
new_uuid(a)          = 3e927fbd-156d-42f9-8f7a-86e19ef86ddc
ещё раз new_uuid(a)  = 3e927fbd-156d-42f9-8f7a-86e19ef86ddc  <- то же самое: детерминизм
ссылка '#_' + a      = #_3e927fbd-156d-42f9-8f7a-86e19ef86ddc  <- UUID внутри строки заменён так же

Объектов: 15, внутренних ссылок: 5, битых ссылок: 0
```

Скрипт записал `practice/out_step04.xml`. Откройте его и найдите подстанцию и ссылку на неё.

**Проверьте себя.**
1. Почему перед хешированием UUID приводится к нижнему регистру (`old.lower()`)? (В схемах встречаются
   ЗАГЛАВНЫЕ UUID, а это тот же самый идентификатор.)
2. Почему ссылку на перечисление `http://…#CustomerKind.residential` функция не изменит?
   (В ней нет UUID: регулярное выражение его не найдёт.)

**Упражнение.** Поменяйте `SECRET` в скрипте и запустите снова: UUID станут другими, а битых ссылок
по-прежнему будет 0.

**Частые ошибки.** Использовать `random`: при каждом запуске результат будет разный, требование
детерминизма нарушится. Забыть `ET.register_namespace`: в выходном файле появятся префиксы `ns0:`,
`ns1:` вместо `cim:` и `rdf:`.

## Шаг 5. Номера: та же длина, без повторов

## Шаг 8. Регулярные выражения: одна «сеть» для всего текста

**Зачем.** В одном тексте могут оказаться UUID, телефон, номер подстанции, напряжение и имя.
Нужно найти каждый кусок и правильно его заменить.

**Что понять: мини-курс регулярных выражений.**

| Запись | Значит | Пример |
|---|---|---|
| `\d` | цифра | `\d+` найдёт `2303` |
| `+` | один или больше раз | `\d+` — одна или больше цифр |
| `{3,}` | три или больше раз | `\d{3,}` — число из 3+ цифр |
| `[^\W\d_]` | буква (не цифра и не `_`) | `[^\W\d_]+` — слово |
| `\s` | пробельный символ | `[\s.\-]*` — пробелы, точки, дефисы |
| `(?:Sub\|pol)` | «Sub» или «pol» | вариант без запоминания |
| `(?P<имя>…)` | именованная группа | потом спросим `m.lastgroup` |
| `(?!…)` | «дальше НЕ идёт …» | `(?!\s*kV)` — после числа не стоит «kV» |
| `[.,]\d` | точка или запятая, **за которой цифра** | дробная часть: `0,4`, `0.4` |

Главная хитрость — **одно** выражение с вариантами через `|`. Python идёт по тексту слева направо и
в каждой позиции пробует варианты по порядку. Функция `replace` получает найденный кусок и по имени
сработавшего варианта (`m.lastgroup`) решает, на что его заменить. Каждый кусок обрабатывается
**ровно один раз**. Если делать несколько замен подряд, вторая могла бы испортить результат первой.

**Что сделать.**

```bash
python practice/step08_regex.py
```

**Что вы увидите.**

```
'Sub - 2303'           -> найдено: [('Sub - ', '2303')]
'Sub - 2303, рядом'    -> найдено: [('Sub - ', '2303')]
'Sub 138 kV Kangaba'   -> найдено: []
'Sub 110/35 kV'        -> найдено: []
   mnum   'Sub - 2303'
   mnum   'pol.126'
   word   'Sub'
   num    '35'
   word   'kV'
   word   'Ngolona'
   word   'тел'
   phone  '+7 (912) 345-67-89'

Было:   Sub - 2303, pol.126, Sub 35 kV Ngolona, тел. +7 (912) 345-67-89
Стало:  Sub - <НОМЕР>, pol.<НОМЕР>, Sub 35 kV Яблочная, тел. <ТЕЛЕФОН>
```

Номера `2303` и `126` найдены вариантом `marker`, а напряжение `138 kV`, `110/35 kV` и `35 kV` — нет,
благодаря проверке `(?!…)` после номера. Для `Sub 35 kV` вариант `marker` не подошёл (2 цифры, да
ещё и «kV» после), поэтому Python попробовал следующие варианты: `word` для «Sub», `num` для «35».

**Проверьте себя.** Почему в проверке после номера стоит `[.,]\d`, а не просто `[.,]`?
(Ответ: в первой версии программы было `[.,]`, и номер «Sub - 2303, …» с обычной запятой после него
**не заменялся**: запятая принималась за начало дробной части. Дробная часть — это запятая или точка,
**за которой идёт цифра**. Эту ошибку нашёл как раз такой учебный пример.)

**Упражнение.** Добавьте вариант для e-mail `(?P<email>[\w.+-]+@[\w-]+\.[\w.-]+)` и замену `<ПОЧТА>`.

## Шаг 9. Вложения base64 и zip-архивы

**Зачем.** Внутри модели есть закодированные документы: XML участков линий с названиями населённых
пунктов, схемы подстанций в zip-архивах. Их тоже нужно обезличить.

**Что понять.**

* **base64** записывает любые байты латинскими буквами и цифрами. `base64.b64decode` раскодирует
  строку в байты, `b64encode` закодирует обратно.
* Байты, которые начинаются с `PK`, — это zip-архив. Его можно открыть прямо в памяти:
  `zipfile.ZipFile(io.BytesIO(байты))`.
* Байты `EF BB BF` в начале текста — **метка BOM**. Её надо сохранить, а читать текст удобно
  кодировкой `utf-8-sig`, которая метку убирает.
* Картинки и звуки не являются текстом, их не трогаем.

**Что сделать.**

```bash
python practice/step09_base64.py
```

**Что вы увидите.**

```
Внутри: <?xml version="1.0" encoding="utf-8"?>
<Sections>
  <Section ... Name="Участок линии от оп.31 до ПС Тимошкино" />
</Sections>
...
Проверка раскодированием:  Name="Участок линии от оп.31 до ПС Яблочная" />
...
Файл в архиве: diogen/diagram.xml -> <Diagram Description="КТП - 1618" uid="b2000000-…"/>
```

**Важно.** Схема в архиве ссылается на объект модели **по UUID** (`uid="…"`). Поэтому внутри
вложений нужно применять **те же** правила, что и для модели, включая замену UUID. Иначе схема
потеряет связь со своими объектами.

**Что должно получиться.** `out1` и `out2` совпадают байт в байт, `out3` отличается. Причём в `out3`
другие **названия**, а не только UUID.

**Урок из разработки.** В первой версии словарь имён нумеровался по алфавиту, и названия в `out3`
совпадали с `out1`. Тогда, зная список настоящих названий, можно восстановить соответствие: первое
по алфавиту название всегда становилось «Абрикосовой». Исправление — сортировать по хешу с секретом:
`sorted(words, key=lambda w: (h("word:" + w), w))`.

## Приложение А. Словарь терминов

| Термин | Простыми словами |
|---|---|
| XML | текстовый формат «дерево тегов» |
| Тег, элемент, атрибут | `<тег атрибут="значение">текст</тег>` |
| Пространство имён, префикс | `cim:` — сокращение для `http://iec.ch/…`; помогает не путать одинаковые имена тегов из разных стандартов |
| CIM | стандартный способ описать энергосистему объектами классов |
| RDF/XML | способ записать CIM-модель в XML: `rdf:about` — кто я, `rdf:resource` — на кого ссылаюсь |
| UUID | уникальный идентификатор вида `3ca10967-b797-4d15-9a44-cdea3015ad63` |
| Граф связей | объекты (вершины) и ссылки между ними (рёбра) |
| Обезличивание, псевдонимизация | замена настоящих данных выдуманными с сохранением связей |
| Хеш-функция (SHA-256) | превращает текст в число; одинаковый текст — одинаковое число; обратно не восстановить |
| Детерминизм | одинаковый вход всегда даёт одинаковый результат |
| Потоковое чтение | обработка файла по кусочкам, без загрузки целиком |
| Генератор (`yield`) | функция, которая отдаёт значения по одному |
| Регулярное выражение | шаблон для поиска текста: `\d+` — число |
| base64 | запись любых байтов буквами и цифрами |
| BOM | служебные байты `EF BB BF` в начале текстового файла |
| Стоп-список | слова, которые программа не должна считать именами |

## Приложение Б. Частые ошибки новичка

| Ошибка | Как проявляется | Как исправить |
|---|---|---|
| Запуск не из той папки | `FileNotFoundError: practice/mini_model.xml` | перейти в папку: `cd "C:\MX\новый вариант"` |
| Кодировка консоли | `╨Я╤А╨╛…` вместо русских букв | `[Console]::OutputEncoding=[Text.Encoding]::UTF8` |
| `ET.parse` на большом файле | компьютер «зависает», ошибка памяти | `iterparse` + `root.remove` |
| `random` вместо хеша | два запуска дают разные файлы | `hashlib.sha256` с секретом |
| Разные функции для `rdf:about` и `rdf:resource` | `check.py`: «ссылка указывает не на тот объект» | одна функция `replace_uuids` |
| Замена всех чисел подряд | изменились «35 kV», «300/5», «3x185» | менять числа только в оговорённых случаях |
| Несколько замен подряд в одном тексте | вторая замена портит результат первой | одно регулярное выражение с вариантами |
| Нет проверки результата | ошибку находит преподаватель | `check.py` и просмотр примеров глазами |
| Выходной файл = входной | исходные данные потеряны | всегда разные имена файлов |
