# Простое решение «два прохода»: подробная инструкция для новичка

Эта инструкция объясняет **с нуля**, как пользоваться простым решением задачи обезличивания CIM-модели
и как оно устроено внутри. Предполагается, что вы умеете запускать программы из командной строки и
немного знаете Python. Всё остальное объясняется по ходу.

Всё нужное лежит в папке `C:\MX\новый вариант\`. Решение проверено на настоящей модели `input.xml`
(921 МБ, 741 550 объектов). Все выводы программ в этой инструкции — настоящие, полученные при её
подготовке.

---

## 1. Что это за решение и когда его выбирать

Это **самое простое** из проверенных решений: одна программа на Python без дополнительных библиотек,
два прохода по файлу и понятные правила замены. На ней удобно учиться: к каждой строке кода есть
комментарий (файл `anonymize_commented.py`).

| | Простое решение (эта папка) | Вариант 2 с хранилищем |
|---|---|---|
| Качество обезличивания `input.xml` | одинаковое: те же правила замены | одинаковое |
| Сложность | один файл, около 550 строк | плюс хранилище и контроль статистики |
| Повторный запуск на **том же** файле | тот же результат | тот же результат |
| Запуск на **обновлённой** модели (добавили объекты) | часть псевдонимов меняется | старые псевдонимы сохраняются |
| Когда выбирать | учебная задача, разовая передача модели | модель выгружают регулярно |

На настоящей модели разница выглядит так: в `input.xml` добавили три объекта и обезличили заново.
Без хранилища у **118 864** из 741 550 старых объектов поменялось название, с хранилищем — ни у одного.
Если вы передаёте модель **один раз** (например, для курсовой или для одной проверки), это не важно,
и простое решение полностью подходит.

## 2. Простыми словами: что делает программа

### Что такое обезличивание

Модель энергосистемы — это большой XML-файл. В нём описаны подстанции, линии, счётчики, абоненты и
связи между ними. Перед передачей модели посторонним нужно заменить:

* **ФИО** абонентов и сотрудников — на выдуманные из справочника имён;
* **названия** подстанций, линий, организаций — на прилагательные от названий фруктов;
* **номера** счётчиков, подстанций, лицевых счетов — на другие номера той же длины;
* **идентификаторы** объектов (UUID) — на другие UUID.

При этом **связи** между объектами, **типы** объектов («Sub», «OHL»), **напряжения** («35 kV»),
**районы** и **физические параметры** (сопротивления, длины, нагрузки) остаются прежними.

### Псевдоним и секрет

**Псевдоним** — постоянная замена: слово «Ngolona» превращается в «Alychovaya» **везде**, где
встречается: в названии подстанции, линии, измерения, в формуле и даже внутри закодированных
вложений.

Все замены вычисляются из **секретного слова** с помощью хеш-функции SHA-256 (она превращает текст в
длинное число-«отпечаток»). Одинаковый текст при одинаковом секрете всегда даёт одинаковый отпечаток,
поэтому:

* при повторном запуске с тем же секретом получается **тот же** результат;
* без секрета нельзя повторить замены и подобрать настоящие значения.

### Два прохода

Программа читает модель **дважды**:

1. **Первый проход** собирает все настоящие названия: подстанций, линий, организаций, улиц.
   Районы отмечаются как «не трогать».
2. **Второй проход** заменяет значения и сразу записывает результат.

Два прохода нужны потому, что формула или комментарий может стоять в файле **раньше** самой
подстанции. После первого прохода программа уже знает все названия и заменит их везде.

### Почему файл в 1 ГБ не занимает 1 ГБ памяти

Программа читает файл **по одному объекту**: прочитала подстанцию, обработала, записала, удалила из
памяти, взяла следующую. Памяти нужно несколько десятков мегабайт, сколько бы ни весил файл.

## 3. Подготовка

### 3.1 Python

Нужен Python 3.8 или новее. Дополнительные библиотеки **не нужны**. Проверка:

```bash
python --version
```

Если команда не найдена, установите Python с python.org и при установке отметьте
«Add python.exe to PATH». В Windows можно попробовать `py` вместо `python`.

Откройте терминал (PowerShell) и перейдите в папку. В названии папки есть пробел, поэтому путь

```bash
cd "C:\MX\новый вариант"
```

```bash

```

Это проблема отображения в консоли, а не программы и не файлов.

```bash
python tools\test_rules.py
```

Последняя строка должна быть `Тестов: 20, ошибок: 0`. Значит, Python работает, справочники на месте и
правила замены ведут себя правильно.

## 7. Шаг 4. Повторяемость и роль секрета

**Тот же секрет — тот же результат.** Запустите программу ещё раз с тем же секретом в другой файл:

```bash
python anonymize.py practice\mini_model.xml practice\out_v1_again.xml учебный-секрет
```

Сравните контрольные суммы двух файлов:

```bash
Get-FileHash practice\out_v1.xml, practice\out_v1_again.xml
```

Суммы совпадают: файлы одинаковы до последнего байта.

**Другой секрет — другие замены.**

```bash
python anonymize.py practice\mini_model.xml practice\out_other.xml другой-секрет
```

| Объект | Секрет «учебный-секрет» | Секрет «другой-секрет» |
|---|---|---|
| подстанция | Sub 35 kV Alychovaya | Sub 35 kV Ayvovaya |
| номер подстанции | Sub - 3095 | Sub - 6452 |
| линия | OHL 35 kV Alychovaya - Arbuznaya | OHL 35 kV Ayvovaya - Ananasovaya |
| организация | LLC UK DOM ABRIKOSOVAYA | LLC UK DOM ALYCHOVAYA |

Поэтому секрет нужно **запомнить**: чтобы через месяц получить те же псевдонимы для той же модели,
нужен тот же секрет. И **не передавать** его: зная секрет, можно повторить вычисления и проверить
догадку о настоящем названии.

## 8. Шаг 5. Ограничение: обновлённая модель

Файл `practice\mini_model_v2.xml` — это «следующая выгрузка»: в **начало** модели добавили подстанцию
«Kati» и линию «Kati - Ngolona». Обезличим её с тем же секретом:

```
Проход 2: объектов 17, ФИО 4, base64-вложений 1, заменённых номеров 8 — 0 с
Готово: practice\out_v2.xml (0 МБ) за 0 с
```

Сравните названия с первой выгрузкой:

| Объект | Первая выгрузка (`out_v1`) | Обновлённая модель (`out_v2`) |
|---|---|---|
| новая ПС Kati | — | Sub 35 kV Abrikosovaya |
| ПС Ngolona | Sub 35 kV **Alychovaya** | Sub 35 kV **Ananasovaya** |
| линия | OHL 35 kV Alychovaya - Arbuznaya | OHL 35 kV Ananasovaya - Artishokovaya |
| организация | LLC UK DOM ABRIKOSOVAYA | LLC UK DOM AYVOVAYA |
| номер подстанции | Sub - 3095 | Sub - 3095 |

Номера, ФИО и UUID остались прежними: они вычисляются из хеша самого значения. А **названия
поменялись**.

**Почему.** Каждое настоящее название получает **порядковый номер**, номер определяет прилагательное
(0 → «Абрикосовая», 1 → «Айвовая», 2 → «Алычовая», …). Номера раздаются заново при каждом запуске, по
порядку, который задаёт хеш. Новое слово «Kati» встало в очередь первым, забрало номер 0, и все
остальные сдвинулись на один.

**Как с этим жить:**

* если модель передаётся **один раз** — ограничение не мешает;
* если модель обновилась, обезличьте её заново и передайте получателю **целиком**, предупредив, что
  названия новые и сравнивать их со старой версией нельзя;
* если получатели должны видеть **одни и те же** названия во всех выгрузках, используйте вариант 2
  с хранилищем (`C:\MX\v2_two_pass_vault\real_model`).

## 10. Шаг 7. Посмотреть на результат глазами

Автоматическая проверка не всё замечает. Например, она не увидит, что техническое слово превратилось
во фрукт. Поэтому результат обязательно просматривают.

Первые строки файла (открывать файл на 1 ГБ в редакторе не нужно):

```bash
Get-Content C:\MX\out\input_anon.xml -TotalCount 40 -Encoding utf8
```

Найти подстанции 35 кВ:

```bash
Select-String -Path C:\MX\out\input_anon.xml -Pattern "Sub 35 kV" -Encoding utf8 | Select-Object -First 10
```

Посмотреть словарь названий, который собирает программа:

```bash
python tools\show_words.py C:\Users\Admin\Downloads\input.xml > words.txt
```

В `words.txt` три списка: имена собственные с их заменами, улицы, защищённые слова (районы).

**На что смотреть:**

* в строке `Слова … оставшиеся как есть` отчёта проверки должны быть только технические слова
  (`Line`, `Plant`, `Substation`) и районы (`Koulikoro`, `Farada`);
* в списке имён собственных не должно быть технических слов («Protection», «Отключены»);
* тип объекта в названиях не должен превращаться во фрукт («OHL», «Sub», «ТП»).

## 11. Как устроена программа

### 11.1 Общая схема

```
input.xml ──► ПРОХОД 1 (collect) ──► имена собственные, улицы, районы
                                        │
                                        ▼
                            build_word_map: слово № i → прилагательное № i
                                        │
input.xml ──► ПРОХОД 2 (anonymize) ──► для каждого объекта: process_object
                                        • UUID           → new_uuid
                                        • ФИО            → fake_person
                                        • номера         → new_number
                                        • названия, текст → process_text
                                        • вложения base64 → process_base64
                                        • числа, даты     → без изменений
                                     ──► output.xml
```

### 11.2 Разделы файла `anonymize.py`

| Раздел | Функции | Что делает |
|---|---|---|
| 1. Справочники | `load_tsv`, `translit`, `is_cyrillic` | читает `dict/*.tsv`, переводит в латиницу |
| 2. Детерминизм | `h`, `pick` | число из SHA-256 с секретом; выбор из списка по хешу |
| 3.1 UUID | `new_uuid`, `replace_uuids` | новые идентификаторы, одинаковые для объекта и ссылок |
| 3.2 Номера | `new_number` | номер той же длины, без повторов |
| 3.3 Названия | `build_word_map`, `build_street_map` | словарь «слово → прилагательное», «улица → улица» |
| 3.4 ФИО | `fake_person`, `fake_email`, `fake_phone` | синтетические персональные данные |
| 3.5 Текст | `TOKEN`, `process_text` | одно регулярное выражение для всего текста |
| 3.6 base64 | `decode_base64`, `base64_texts`, `process_base64` | вложенный XML и zip-архивы схем |
| 4. Настройки | `KEY_CLASSES`, `ID_FIELDS`, `STOP_WORDS`, … | какие поля как обрабатывать |
| 5. Чтение | `read_objects`, `leaf_values` | чтение по одному объекту |
| 6. Проход 1 | `collect` | сбор словарей |
| 7. Проход 2 | `process_value`, `process_object`, `anonymize`, `main` | замены и запись |

Полный разбор с комментарием к **каждой** строке — в `anonymize_commented.py`. Читайте его сверху вниз,
раздел за разделом. Код в нём тот же, что в `anonymize.py`; убедиться в этом можно командой


### 11.3 Главные места кода с комментариями

**Хеш с секретом** — основа всех замен:

```python
def h(text):
    # склеиваем секрет и текст, считаем SHA-256, превращаем 64 шестнадцатеричных символа в число
    return int(hashlib.sha256((SECRET + "|" + text).encode("utf-8")).hexdigest(), 16)


def pick(items, text):
    # остаток от деления на длину списка — номер элемента; для одного текста всегда один и тот же
    return items[h(text) % len(items)]
```

**Чтение по одному объекту** — поэтому файл любого размера помещается в память:

```python
for event, elem in ET.iterparse(path, events=("start", "end", "start-ns")):
    ...
    else:                         # закончился какой-то тег
        depth -= 1
        if depth == 1:            # закончился целый объект модели (ребёнок корня rdf:RDF)
            yield elem            # отдаём его на обработку
            root.remove(elem)     # и сразу удаляем из памяти
```

**Новый UUID** — одна функция для объекта и для всех ссылок на него, поэтому связи не рвутся:

```python
def new_uuid(old):
    # хеш старого UUID → 128-битное число → UUID версии 4; регистр букв сохраняем
    new = str(uuid.UUID(int=h("uuid:" + old.lower()) % 2 ** 128, version=4))
    return new.upper() if old.isupper() else new
```

**Номер той же длины без повторов:**

```python
attempt = 0
while True:
    # кандидат: хеш → остаток от деления на 10^длина → дополняем нулями слева
    new = str(h(f"num:{old}:{attempt}") % 10 ** len(old)).zfill(len(old))
    same_kind = (new[0] == "0") == (old[0] == "0")   # ведущий ноль сохраняем как был
    if same_kind and new != old and new not in used_numbers:
        break                                         # подходит: такой номер ещё никому не выдан
    attempt += 1                                      # иначе пробуем следующий вариант
```

**Словарь названий** — каждое слово получает свой номер, а номер — своё прилагательное:

```python
words = sorted(words, key=lambda w: (h("word:" + w), w))   # порядок задаёт хеш с секретом
for i, word in enumerate(words):
    if i < n:
        adjective = FRUITS[i]                              # первые 100 слов: «Яблочная»
    else:
        first, second = divmod(i - n, n - 1)               # дальше — пары разных фруктов:
        ...                                                # «Яблочно-грушевая»
```

Разные слова получают разные номера, поэтому новые названия **уникальны**.

**Одно регулярное выражение для текста.** Варианты проверяются по порядку: UUID, e-mail, телефон,
«тип объекта + номер», число, слово. Каждый кусок текста заменяется ровно один раз:

```python
TOKEN = re.compile(r"""
     (?P<uuid>  …UUID… )
   | (?P<email> …@… )
   | (?P<phone> +7 или 8 и 10 цифр )
   | (?P<marker>(Sub|ПС|TS|РП|pol|№ …)[\s.\-–_№]*)(?P<mnum>\d{3,})(?![\d/]|[.,]\d|\s*(?:kV|кВ…))
   | (?P<num>\d+)
   | (?P<word>[^\W\d_]+)
""", re.VERBOSE)
```

Последняя часть варианта `marker` — проверка «после номера не идёт цифра, дробь или единица
измерения». Благодаря ей в «Sub - 2303» номер меняется, а в «Sub 138 kV» и «Sub 110/35 kV» напряжение
остаётся.

**Что не трогать** — числа, даты и флаги в обычных полях (это физика модели):

```python
if re.fullmatch(r"[-+]?\d*[.,]?\d+([eE][-+]?\d+)?|true|false|\d{4}-\d\d-\d\d.*", value) \
        and field not in ID_FIELDS and field not in NAME_FIELDS:
    return value       # сопротивления, длины, мощности, даты — без изменений
```

## 12. Настройка под другую модель

Правила настроены на выгрузку СК-11 (`input.xml`). Для модели из другой системы:

1. Узнайте, какие классы и поля есть в модели:

```bash
python tools\explore.py новая_модель.xml > explore_report.txt
```

2. В разделе 4 файла `anonymize.py` поправьте наборы:

| Набор | Что в него вписать |
|---|---|
| `KEY_CLASSES` | классы, из названий которых собираются настоящие имена (`Substation`, `Line`, …) |
| `REGION_CLASSES` | классы районов и регионов: их названия сохраняются |
| `ID_FIELDS` | поля-идентификаторы: в них заменяются все числа из 3+ цифр |
| `NUMBER_NAME_CLASSES` | классы, у которых название — это номер (счётчик, опора) |
| `PERSON_FIELDS` | поля, где целиком записано ФИО |
| `IP_PREFIXES` | как начинается название индивидуального предпринимателя |
| `MARKERS`, `UNITS` | типы объектов, после которых идёт номер; единицы измерения |

3. Посмотрите словарь и уберите технические слова через `STOP_WORDS`:

```bash
python tools\show_words.py новая_модель.xml > words.txt
```

Будьте внимательны: «Центральная», «Восход», «Новая» — это обычно **названия подстанций**, их в
стоп-список не добавляют.

4. Добавьте свои примеры в `tools\test_rules.py` и запустите тесты, затем мини-модель, затем полный файл.

Если меняете `anonymize.py`, внесите то же изменение в `anonymize_commented.py` и проверьте
`python tools\verify_same.py`.

## 13. Безопасность

| Что | Где хранить | Кому передавать |
|---|---|---|
| исходная модель | там же, где раньше, под защитой | никому |
| секретное слово | в менеджере паролей или в сейфе | никому |
| обезличенная модель | — | получателю |

* Таблица «было → стало» **нигде не сохраняется**: она существует только в памяти во время работы.
* Не используйте учебные секреты (`учебный-секрет`, `secret`) для настоящих данных.
* Исходный файл программа не изменяет. Если по ошибке указать выходным файлом входной, исходные
  данные будут перезаписаны, поэтому всегда давайте результату **другое** имя.

## 14. Частые ошибки и что делать

| Сообщение или симптом | Причина | Что делать |
|---|---|---|
| `python` не найден | Python не установлен или не добавлен в PATH | установите Python с галочкой PATH или используйте `py` |
| `cd` не находит папку | в пути есть пробел | возьмите путь в кавычки: `cd "C:\MX\новый вариант"` |
| `╨Я╤А╨╛…` вместо русских букв | кодировка консоли | `[Console]::OutputEncoding = [Text.Encoding]::UTF8` |
| `FileNotFoundError: … dict\names.tsv` | папка `dict` не рядом с `anonymize.py` | не разносите файлы по разным папкам |
| `FileNotFoundError` для входного файла | неверный путь | проверьте путь; пути с пробелами — в кавычках |
| `ParseError: … line N` | входной файл повреждён или обрезан | файл должен заканчиваться на `</rdf:RDF>` |
| `Слишком много имён собственных` | названий больше 10 000 | добавьте фрукты в `dict/fruits.tsv` или проверьте словарь через `show_words.py` |
| два запуска дали разные файлы | отличаются секрет, справочники или версия программы | при тех же условиях результат одинаковый |
| после обновления модели «всё переименовалось» | так устроено простое решение (см. шаг 5) | передайте модель целиком заново или используйте вариант 2 |
| `check.py`: «в файлах разное число объектов» | обезличивание было прервано | запустите заново |
| `check.py`: «изменился числовой параметр» | правило задело физическое значение | найдите поле по примеру и добавьте его в исключения |

## 16. Словарь терминов

| Термин | Простыми словами |
|---|---|
| CIM-модель | описание энергосистемы объектами классов (подстанция, линия, счётчик) и ссылками между ними |
| XML, тег, атрибут | текстовый формат «дерево тегов»: `<тег атрибут="значение">текст</тег>` |
| UUID | уникальный идентификатор объекта вида `3ca10967-b797-4d15-9a44-cdea3015ad63` |
| `rdf:about`, `rdf:resource` | «кто я» (идентификатор объекта) и «на кого ссылаюсь» (ссылка) |
| Обезличивание, псевдонимизация | замена настоящих данных выдуманными с сохранением связей |
| Псевдоним | постоянная замена одного и того же значения |
| Хеш (SHA-256) | превращает текст в число-«отпечаток»; обратно не восстановить |
| Секретное слово | добавляется к тексту перед хешированием, чтобы посторонний не мог повторить замены |
| Два прохода | файл читается дважды: сначала сбор словаря, потом замены |
| Потоковое чтение | файл читается по одному объекту, весь файл в память не загружается |
| Стоп-список | слова, которые программа не считает названиями (Sub, OHL, Protection…) |
| base64 | способ записать любые байты буквами и цифрами; так в модели хранятся вложения |
| Регулярное выражение | шаблон для поиска в тексте: `\d+` — число, `[^\W\d_]+` — слово |
